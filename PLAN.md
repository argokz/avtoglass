# План: оптовая закупка и быстрая розница

Дата: 2026-09-09. Статус: согласование.

## Зачем

Сейчас опт — это только скидка от розницы в том же интерфейсе: карточки, корзина,
оформление. Оптовику (сервис, таксопарк, перекуп) это не подходит: он берёт
не «стекло на машину», а **список позиций** — по еврокоду/артикулу, галочками,
с количеством, одной заявкой-спецификацией. Корзина с «шагами» ему мешает.

Рознице, наоборот, нужно **меньше** интерфейса: два поля и одна кнопка,
одинаково быстро на компьютере и телефоне.

## Принципы (не нарушаем)

1. Закуп (`offers.price_wholesale`) — себестоимость, на витрину не попадает нигде.
2. Оптовая цена = розница минус скидка менеджера, не ниже закупа (уже есть:
   `Customer::wholesalePrice()`, `Offer::sellingPrice()`).
3. Опт включает только менеджер (статус `WholesaleStatus::Wholesale`). Самозаписи нет.
4. Розничный сценарий гостя не ломаем: заявка без регистрации остаётся.
5. Каждый этап закрывается тестами. Миграции на живую базу — с подтверждения.

## Этап 1. Оптовая заявка-спецификация (ядро, без UI)

**Статус: сделано 2026-09-09.** `OrderSource::Wholesale`, `CreateOrder::fromWholesaleSelection()`,
`POST /opt/zayavka` под `auth + OnlyCustomers + OnlyWholesale`, пороги
`wholesale_min_total`/`wholesale_min_qty` в настройках CRM (раздел «Опт»),
12 тестов в `tests/Feature/WholesaleOrderTest.php` — зелёные.

Цель: один заказ из N позиций по оптовым ценам, создаваемый одним действием.

- 1.1. `OrderSource::Wholesale` (`wholesale`, «Оптовая заявка») + бейдж/цвет в Filament.
- 1.2. `CreateOrder::fromWholesaleSelection(Customer $customer, array $positions)`:
  - позиции: `[offer_id => qty]`, цена — `Offer::sellingPrice($customer)` (снимок в `order_items`);
  - без онлайн-оплаты: `payment_method = null`, оплата по счёту/при получении — решает менеджер;
  - `fulfillment`: только `pickup`/`delivery` (оптовик ставит сам; установка не предлагается);
  - комментарий: организация, БИН, скидка % (уже умеет `buildComment`);
  - задача менеджеру «Оптовая заявка {number}» (due 1 час, не 15 минут — не горит);
  - без `AnnounceNewOrder` в Telegram? — оставить как у остальных, канал тот же.
- 1.3. Маршруты:
  - `GET /opt` — оптовая витрина (этап 2);
  - `POST /opt/zayavka` — приём спецификации;
  - middleware: `auth` + `OnlyCustomers` + свой `OnlyWholesale` (403/редирект с объяснением).
- 1.4. Тесты (`tests/Feature/WholesaleOrderTest.php`):
  - оптовик: 3 позиции → один `Order` source=wholesale, цены оптовые, задача создана;
  - розничный клиент / гость → 403;
  - pending → 403;
  - пустой список / qty=0 → ошибка валидации;
  - цена не ниже закупа при скидке 40%.

## Этап 2. Оптовая витрина `/opt` — таблица с галочками

**Статус: сделано 2026-09-09.** Livewire `WholesaleTable`: поиск по еврокоду/OEM/артикулу/названию,
фильтры (тип, марка стекла, наличие), галочки + количество, липкий итог,
отправка обычным POST на `wholesale.store` (одна валидация). Экраны для
pending/retail/гостя. 10 тестов в `tests/Feature/WholesaleTableTest.php` — зелёные.

Цель: выбрать стёкла галочками, проставить количество, отправить. Без корзины.

- 2.1. Livewire-компонент `App\Livewire\WholesaleTable` + `resources/views/livewire/wholesale-table.blade.php`:
  - строка: чекбокс | фото | название | еврокод | OEM | наличие | цена опт | кол-во (stepper) | сумма;
  - выбранное хранится в свойствах компонента (`selected = [offerId => qty]`), сессия-корзина не используется;
  - липкая панель итога: «Выбрано N позиций · X шт · Y ₸» + кнопка «Отправить заявку»;
  - на мобильном строка превращается в карточку (та же разметка, grid → block).
- 2.2. Поиск внутри таблицы: еврокод / OEM / артикул / название (`pg_trgm` уже включён,
  `ProductFilter.query` переиспользуем); без перезагрузки (wire:model.live.debounce).
- 2.3. Фильтры: тип стекла, «только в наличии», марка стекла (supplier). Год/модель —
  вторичны, оптовик знает еврокод; оставить один необязательный фильтр по модели.
- 2.4. Сортировка по умолчанию: наличие → цена. Пагинация 50 (не 24).
- 2.5. Пустые состояния: pending → «заявка на проверке»; retail → «подайте заявку на опт»
  (ссылка в профиль); гость → редирект на вход.
- 2.6. Отправка: подтверждение (итог + способ получения + адрес при доставке) →
  `CreateOrder::fromWholesaleSelection` → редирект на «спасибо»/заказ.
- 2.7. Тесты Livewire: выбор/снятие, количество, итог, поиск сужает список, отправка.

## Решения (2026-09-09, согласовано)

- Оплата опта: при отправке заявки оплаты нет. Менеджер после рассмотрения
  решает — счёт, онлайн-оплата или при получении. Заявка создаётся без
  `payment_method`, онлайн-оплата не стартует автоматически.
- Получение опта: только `delivery` и `pickup`. Установки и выезда нет.
- Минимальный порог заявки: настраивается менеджером в CRM
  (`wholesale_min_total`, `wholesale_min_qty`), по умолчанию 0 — любая заявка.
