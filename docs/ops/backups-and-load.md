# Бэкапы и нагрузочное тестирование

## Бэкапы

Дамп базы содержит персональные данные (телефоны, адреса — в шифротексте,
но ключ приложения рядом с дампом не хранят). Регламент:

- `pg_dump` базы `avtoglasskz` — ежедневно, хранение 14 дней локально и 35 дней вне площадки.
- Дамп шифруется отдельным ключом (GPG/age), ключ приложения в архив не входит.
- Раз в месяц — контрольное восстановление на staging: бэкап, который не разворачивается, не бэкап.
- `storage/app/public` (снимки товаров, варианты WebP) — ежедневная синхронизация; варианты восстановимы командой `media:variants`, оригиналы — нет.

Проверка восстановления:

```bash
pg_restore -d avtoglasskz_restore dump.pgc
php artisan migrate:status --database=pgsql_restore
```

## Нагрузочное тестирование

Сценарий `scripts/load/storefront.js` (k6): главная → каталог → поиск,
пороги p95 < 800 мс и ошибок < 1%. Запуск только против изолированного
preview на 127.0.0.1:8015 с синтетическими данными:

```bash
k6 run -e BASE_URL=http://127.0.0.1:8015 scripts/load/storefront.js
```

Перед прогоном: `php artisan config:cache`, прогреть OPcache, воркеры
очередей default и ai запущены. После изменений в поиске и checkout
прогон обязателен — trigram-запросы чувствительны к росту таблиц.

## Срок хранения персональных данных

`pdn:anonymize` (планировщик, ежедневно) анонимизирует карточки клиентов
без кабинета, чьи заявки закрыты дольше `PDN_RETENTION_MONTHS` (по умолчанию
36 месяцев). Проверка объёма перед включением: `php artisan pdn:anonymize --dry-run`.
