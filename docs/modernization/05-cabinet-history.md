# Этап 1, часть 5 — вход по коду и история заказов

Дата: 18 сентября 2026 года. Требования: разделы 9, 15 и 17 [спецификации](../../MODERNIZATION_SPEC.md). Продолжение [файлового импорта и повторения](04-file-import-repeat.md).

## 1. Что доступно

В [прототипе покупки](http://127.0.0.1:8015/preview/ux?view=orders) раздел «Мои заказы» теперь открывает вход по коду, затем список нескольких заказов. Есть поиск, фильтры, страницы, отдельная карточка, объяснения доступных действий и сохранение изменений в рамках текущей сессии.

Это интерфейсная часть этапа 1. Вход работает через демонстрационный код и собственное пространство сессии. Реальные SMS, Laravel Auth, рабочие клиенты и заказы не затрагиваются. Существующий production-кабинет с паролем пока сохранён; переход на SMSC.kz требует этапа 3 и миграции привязок аккаунтов.

## 2. Вход и возврат к покупке

1. Выбрать товар и открыть «Мои заказы» — состав подбора сохраняется.
2. Ввести демонстрационный номер `+77000000001`. Он открывает 25 синтетических примеров заказов. Для другого корректного номера история пустая, кроме заказов, созданных и затем присоединённых в этой же гостевой сессии.
3. Нажать «Получить код». На стенде код явно показан под подписью «Код для проверки прототипа»; SMS не отправляется.
4. Фокус переходит в одно поле из шести цифр. Поддерживаются вставка, числовая клавиатура, `autocomplete="one-time-code"` и отправка Enter.
5. После подтверждения открывается история или заказ, указанный в исходной ссылке. Гостевые заказы этой сессии присоединяются к вошедшему демонстрационному владельцу.
6. Кнопка «Продолжить заказ без входа» возвращает к сохранённому подбору. Вход не является условием оформления розницы.
7. «Выйти из кабинета» закрывает историю и очищает выбранный заказ/предложение из текущего компонента. Перечень заказов другого номера не открывается по угадываемому номеру.

### Состояния кода

| Ситуация | Поведение прототипа |
|---|---|
| Неверный формат телефона | Ошибка у телефона; код не создаётся |
| Отправка | Кнопка недоступна на время запроса |
| Код получен | Маскированный телефон, поле кода и таймер повтора |
| Неправильный код | Ошибка у поля, число оставшихся попыток; история закрыта |
| Прошло 5 минут | Сервер отклоняет код |
| Код уже использован | Повторное применение отклоняется; challenge удалён |
| Повтор ранее 60 секунд | Сервер отклоняет запрос; таймер в браузере только отображает срок |
| Новый код | Прежний код больше не подходит |
| 5 неверных вводов | Текущий challenge блокируется |
| 10 ошибок за 15 минут на номер | Смена формы или новый challenge не обнуляют счётчик этого номера |
| Лимит отправок | В сессии применяются 5 отправок/час и 10/сутки на номер |
| Перезагрузка | Экран действующего или истёкшего challenge восстанавливается; введённый код не сохраняется |
| Ошибка доставки | Отдельный пример в панели состояний; понятное сообщение без открытия кабинета |

Фиктивный код меняется при повторной отправке. В challenge хранится HMAC, но демонстрационная последовательность позволяет показать тестовый код в интерфейсе. Эта схема предназначена **только для preview** и не является production-генератором OTP.

Счётчики здесь сессионные. Общие ограничения по телефону/IP, атомарное использование challenge, случайный production-код, SMS-адаптер, обработка конфликтов аккаунта, роли и аудит должны быть реализованы в общем backend. Текущие тесты не доказывают готовность production-аутентификации.

## 3. История и фильтры

После входа показываются номер, дата, вид покупки, краткий состав, итог, состояние заказа, состояние оплаты и следующий шаг.

- Активные заказы расположены выше завершённых и отменённых. Внутри группы — новые сначала.
- Страница содержит до 20 заказов; в стандартном примере 25 заказов и две страницы.
- Поиск работает по номеру, локализованному названию товара и артикулу как поиск подстроки. Морфологический или семантический поиск этой частью не реализован.
- Фильтры: статус, розница/опт, весь период/30/90 дней. Изменение фильтра возвращает первую страницу; кнопка сброса очищает все фильтры.
- В URL сохраняются `view`, `q`, `status`, `mode`, `period`, `page`, `order`. По перезагрузке восстанавливаются список и фильтры; прямая ссылка на карточку требует входа.
- Возврат из карточки сохраняет фильтры списка. При переходе к повторной покупке ссылка выбранного исторического заказа очищается.
- Есть пустой результат, индикатор обновления, недоступные кнопки предыдущей/следующей страницы и сообщение о недоступном заказе.

Пример ссылки после входа: `/preview/ux?view=orders&mode=wholesale&period=30`. Параметры описывают интерфейс и не предоставляют доступ к заказам без серверной проверки демонстрационного владельца.

В сессии хранится весь небольшой набор примеров, но в разметку списка выводится только текущая страница. Выборка 20 записей из production-БД, индексы, SQL-профиль и проверка N+1 относятся к следующему этапу; текущие результаты не являются доказательством производительности реальной истории.

## 4. Карточка и действия

Карточка загружается при выборе конкретного номера. Она показывает снимок артикулов, производителей, количества, цен, общую сумму, вид получения и сохранённый адрес, состояние оплаты, полученную сумму, события и обращения. Состояние платежа отделено от статуса заказа.

| Заказ | Доступные действия |
|---|---|
| Новый/на согласовании, без платежа и удалённых строк | Редактировать, отменить заявку после явного подтверждения, повторить |
| Есть платёж или платёж обрабатывается | Запросить изменение у менеджера, повторить; прямое редактирование/отмена запрещены и сервером |
| Подтверждён/запланирован | Запросить изменение или отмену через менеджера, повторить |
| Завершён/отменён | Просмотреть и повторить; видна причина отсутствия редактирования |
| Содержит удалённое предложение | Изменение через менеджера; повтор с явным разрешением удалённых строк из части 4 |

Примеры:

- `DEMO-1042` — подтверждённая розничная покупка. Из неё можно отправить запрос изменения и проверить предложение менеджера.
- `DEMO-1501` — оптовая заявка на согласовании. Доступна самостоятельная отмена; результат остаётся в истории после перезагрузки.
- `DEMO-1502` — новый заказ с обрабатываемым платежом. Прямое изменение запрещено независимо от раннего статуса заказа.
- «Пример заказа с удалённой позицией» добавляет `DEMO-2090` в историю текущего демонстрационного владельца.

Новые отправленные заказы получают разные номера и сохраняются рядом с прежними. Повторный вызов отправки уже показанного результата не создаёт ещё один заказ. Это локальная защита состояния интерфейса; защита конкурентных HTTP-запросов и ключи идемпотентности будут реализованы в этапе 2.

Редактирование сохраняет номер, исходную дату, обращения и журнал, увеличивая версию. Перед сохранением сравнивается ожидаемая версия с сохранённым снимком в сессии. Отмена также проверяет версию. Предложения менеджера, их принятие/отказ и обращения сохраняются вместе с соответствующим заказом и восстанавливаются при повторном открытии.

Документы для синтетических примеров не выдаются; экран честно показывает отсутствие документов. Реальные счета/чеки, приватная выдача файлов, актуальное исполнение, доплата и возврат пока не подключены.

## 5. Код и границы хранения

| Файл | Ответственность |
|---|---|
| `app/Livewire/Preview/PreviewOrderBook.php` | Сессионный реестр снимков, генерация примеров, номера и присоединение гостевых заказов |
| `app/Livewire/Preview/Concerns/SignsIntoCabinet.php` | Демонстрационный challenge, серверные проверки срока/попыток, вход и выход |
| `app/Livewire/Preview/Concerns/BrowsesPurchaseHistory.php` | Фильтры/страницы/карточка, сохранение событий, причины ограничения действий |
| `app/Livewire/Preview/PurchaseJourney.php` | Связь истории с текущими путями покупки, изменения и результата |
| `resources/views/livewire/preview/cabinet-login.blade.php` | Вход, ошибки, таймер и продолжение без входа |
| `resources/views/livewire/preview/order-history.blade.php` | Список и фильтры |
| `resources/views/livewire/preview/orders.blade.php` | Карточка заказа и действия |
| `tests/Browser/helpers/preview-cabinet.js` | Вход и открытие заказа через настоящий интерфейс в браузерных проверках |

Состояние хранится в ключах `modernization.preview_*` и существующем `modernization.purchase_preview`. Выбранный снимок/владелец защищены `Locked`. В [части 6](06-profile-templates.md) черновики разделены по владельцам; при смене владельца между Livewire-запросами устаревший запрос отклоняется с 409 и требует перезагрузки. «Начать заново» очищает только демонстрационные пространства.

До входа доступен собственный гостевой результат оформления и исходный публичный учебный пример; список кабинета не показывается. Предсказуемые номера и действия панели симуляции допустимы только на закрытом окружением маршруте `preview`. Не переносить их в production-контроллеры.

```powershell
./scripts/test.ps1 tests/Feature/PurchaseCabinetPreviewTest.php tests/Feature/PurchaseJourneyPreviewTest.php tests/Feature/PurchaseReviewPreviewTest.php tests/Feature/PurchaseFilePreviewTest.php --log-junit .codex/modernization/cabinet-final-tests.xml

npm run build
```

- Итоговый PHP-прогон: **43 теста / 331 assertions, успешно**. Включены 11 новых сценариев кабинета и три прежних компонентных набора покупки/согласования/импорта. Первый прогон имел одну ошибку ожидания в тесте поиска («камера» не является подстрокой «камеры»); проверка исправлена на предусмотренный поиск подстроки.
- Новый браузерный набор: **6 сценариев, успешно** — по три на desktop и Pixel 7. Проверены закрытая история до кода, страницы/фильтры/URL/перезагрузка, карточка/выход, ошибочный и истёкший код на казахском, сохранение гостевого подбора, запрет прямого изменения при платеже и сохранение отмены.
- Отдельная регрессия прежних браузерных путей: **12 сценариев, успешно** — розничное оформление, запрос изменения, повтор с удалёнными строками, принятие/истечение/конфликт предложения и отказ на казахском на desktop/mobile. Новый набор и регрессия выполнены двумя отдельными прогонами, всего 18 сценариев.
- Дополнительно проверены 320 px и 1440 px в тёмной теме: код RU/KK, казахский список с фильтром и русская карточка. Переполнения по горизонтали и ошибок JavaScript нет; получение/отправка кода работают с Enter, фокус устанавливается на поле. Визуально просмотрены узкий экран кода, тёмная история и узкая карточка.
- Vite build, Pint, соответствие 303 ключей RU/KK и `git diff --check` успешны. Проверка в Safari, экранным диктором и с реальной экранной клавиатурой ещё требуется.

Артефакты: `.codex/modernization/cabinet-final-tests.{xml,log}`, `cabinet-browser.log`, `cabinet-regression-browser.log`, `cabinet-final-build.log`, `cabinet-style.log`; снимки в `.codex/modernization/screenshots/05-cabinet/`.
