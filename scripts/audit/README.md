# Воспроизведение аудита 9 октября 2026

Это диагностические инструменты, не изменение витрины. Результат: `docs/audit-2026-10-09/REPORT.md`; сырые данные: `output/playwright/audit-2026-10-09/`.

## Безопасный порядок

1. Сохранить `git status`, HEAD и контрольные суммы `.env*`, `app`, `resources`, `routes`. Прочитать README, MODERNIZATION_SPEC и инструкции preview. Не выполнять `composer setup`.
2. Запустить существующий preview на свободном 18015 по README; `GET /preview/health` обязан вернуть `avtoglass-isolated-v1`. `environment.php --env=preview` обязан показать `avtoglasskz_modernization_preview`. Порт 8015 в этом запуске занят другим приложением; 404 нельзя игнорировать.
3. `isolated-postgres.php` создаёт отдельный локальный кластер 5441 и копирует только синтетическую preview-БД. Он требует свободного порта, установленного PostgreSQL 16 и отсутствующего целевого экземпляра/БД. Он намеренно не переустанавливает существующую БД. Дамп и cluster остаются частными локальными артефактами.
4. `start-load.ps1` запускает четыре новых CGI и отдельный nginx 18016. Пути к PHP/nginx/репозиторию в конфигурации относятся к этой машине; на другой машине их необходимо явно согласовать. Повторно проверить health и порт БД. Не посылать нагрузку на рабочий URL.
5. Выполнить браузерные измерения, затем Lighthouse, затем функциональные диагностические сценарии, затем увеличить **только отдельную БД 5441** через `load-fixtures.php` и последовательно выполнить k6. Сохранить версии инструментов. Не запускать параллельно нагрузку и измерения.
6. PHPUnit запускать последовательно через `scripts/test.ps1`; не обходить `TestDatabaseGuard`. Общий PostgreSQL может исчерпать лимит соединений даже при разных именах БД. Не завершать подключения других проектов.
7. Завершить только созданные аудитом процессы с проверкой PID/command line; отдельный PostgreSQL останавливать `pg_ctl -D <audit-cluster> -m fast -w stop`. Для nginx использовать его отдельный prefix, config и pid. Рабочие CGI, очереди и PostgreSQL 5440 не останавливать.

`stop.ps1` использован для завершения **конкретного запуска 9 октября**. Его preview PID зафиксированы для этого запуска; для нового запуска сначала записать собственные PID и заменить записи, затем проверить command line. Не запускать его как общий stop-all. CGI берутся только из локального `load-php-pids.json`, nginx проверяет audit-prefix, кластер остаётся на диске.

## Команды измерений

```powershell
$env:PREVIEW_URL='http://127.0.0.1:18016'
$env:AUDIT_PHASE='measurements' # screens для 96 комбинаций ширины/темы
node scripts/audit/browser.mjs
node scripts/audit/lighthouse.mjs
node scripts/audit/interactions.mjs
node scripts/audit/checkout.mjs
& C:/php/php.exe scripts/audit/check-order.php --env=preview --isolated
& C:/php/php.exe scripts/audit/load-fixtures.php
# Каждый следующий запуск — после завершения предыдущего.
& <k6.exe> run --env VUS=1 --summary-export output/playwright/audit-2026-10-09/load-1.json scripts/audit/load.js
# Аналогично VUS=10,20,50 и отдельные файлы результатов.
node scripts/audit/summarize.mjs
```

`AUDIT_ONLY=checkout` сохраняет отдельный `browser-checkout.json`; summarizer заменяет им только группы checkout. Этот режим исправляет ошибку исходного измерителя: повторный переход к тому же hash не является загрузкой документа. Все новые навигации сначала открывают `about:blank`, сохраняя HTTP-кеш контекста.

Существующий lock не содержит уже объявленный в package.json `@lhci/cli`. В этом запуске локально установлен `@lhci/cli@0.15.1` вместе с `@playwright/test@1.63.0` через `npm install --no-save --package-lock=false --ignore-scripts`; lock не менялся. Браузеры установлены штатным Playwright. k6 взят из официального GitHub release Grafana, не добавлен в системный PATH.

Lighthouse сохраняет 80 JSON/HTML: восемь экранов × пять запусков × два согласованных профиля. Это simulated throttling с холодным HTTP-кешем каждого прогона. Оформление встроено в корзину: Lighthouse использует URL документа без hash, поскольку автоматическая прокрутка иногда даёт Lantern NO_LCP. Отдельного независимого LCP оформления не объявляем; открытие формы измеряется как взаимодействие. Навигационный измеритель отдельно сохраняет пять cold/warm в desktop/mobile; cold очищает HTTP-кеш, не серверный кеш. Снимки layout выполняются отдельно. Синтетическое увеличение каталога происходит **после** этих замеров: результаты нагрузки нельзя выдавать за замеры на малом baseline-каталоге и наоборот.

Для нагрузочного этапа в этом запуске отдельный nginx был перезапущен с локальной копией конфигурации, где `fastcgi_pass` указывает только на 9124: один активный CGI соответствует проверенному рабочему `fastcgi_pass 127.0.0.1:9123`. Четыре созданных CGI не означают четыре активных worker нагрузки. Для повторения сначала проверить актуальную рабочую конфигурацию, потом выбрать сопоставимую локальную. Исходный `scripts/load/storefront.js` дополнительно проверен на этом же изолированном URL; он сам не имеет health-guard, поэтому отдельная проверка идентичности перед его запуском обязательна.

Фактические четыре прогона использовали shortcut constant-VUs 60 с и стандартный gracefulStop 30 с. Первоначальный неподдерживаемый верхнеуровневый gracefulStop=15 был проигнорирован k6 с предупреждением; результаты отражают 30 с. Скрипт исправлен на явный executor с тем же фактическим gracefulStop=30, без повторного изменения измеренных результатов. Настройки нагрузки, предупреждение и число прерванных итераций сохраняются в raw-log.

Первый 50 VU завершился отказом самого audit-CGI: слушатель исчез, исходный exit code не записан. Сохранён как `load-50-worker-exit.*`; гипотеза стандартного CGI max_requests=500 не считается доказанной. `start-load.ps1` теперь передаёт `PHP_FCGI_MAX_REQUESTS=0` только создаваемым worker, восстанавливая среду запускающей оболочки. В production требуется отдельное управление жизненным циклом процессов. Повтор 50 VU не дал HTTP-ошибок среди завершённых ответов, но все 50 итераций прерваны до товара и /opt: нулевые метрики пустых групп нельзя считать выполнением бюджета. После прерывания нагрузки дождаться разгрузки server backlog перед новым прогоном; первый legacy-повтор с остаточной очередью архивирован отдельно.

После `summarize.mjs` выполнить `publish-measurements.mjs`: он публикует только агрегаты в `docs/audit-2026-10-09/MEASUREMENTS.md`, включая ограничения выборок и окончательный legacy-повтор.

## Реальный ИИ

`ai.php` запускает собственный worker и очередь, разрешает только текущий бесплатный Gemini/локальный endpoint, использует настоящие AssistantDialog/Tools и ограничивает физические HTTP обращения: 150 и 40 минут. `--extra` продолжает тот же глобальный бюджет; основной запуск создаёт новый. Не запускать основной режим поверх активного worker, одновременно или для обхода бюджета. Прекращение после четырёх подряд отказов защищает квоту; неоценённые случаи остаются ограничением.

`score-ai.mjs` проверяет основную rubric фактов/действий. Дополнительные случаи требуют отдельной интерпретации: оптовые цены отличаются от розничных. Сохранить снимок каталога и исходные случаи перед запросами. Не считать preview-демо оценкой реальной модели. Не печатать ключи и не подключать платный billing.
